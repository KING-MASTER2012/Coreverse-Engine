# Continuous integration

Workflows live in `.github/workflows/`; `ci.yml` is the entry point.

| Workflow                                                | What it does                                                                                                                                                                                                                                                                                                                     |
|:--------------------------------------------------------|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `rust.yml`                                              | Cargo test on Linux (bootstrap toolchain, plus the `no_std` math backend); `cargo test` on Windows and macOS; `cargo check` and Clippy of the `platform` crate for `aarch64-linux-android` and `aarch64-apple-ios` (nothing links); a smoke test of the desktop window backend on Xvfb (with and without a window manager)       |
| `cpp.yml`                                               | C++/Qt builds and tests on Linux (GCC, Xvfb, software Vulkan with validation, Wayland test), Windows (MSVC) and macOS (Apple Clang)                                                                                                                                                                                              |
| `lint.yml`                                              | Clippy with `-D warnings`, Rustdoc                                                                                                                                                                                                                                                                                               |
| `formatting.yml`                                        | `cargo fmt --check`, clang-format over C++ and Objective-C++                                                                                                                                                                                                                                                                     |
| `cache-warm.yml`                                        | Nightly run of `cpp.yml` on the default branch: keeps the vcpkg binary cache from expiring and refreshes it after a runner image update                                                                                                                                                                                          |
| `codeql.yml`, `dependency-review.yml`                   | Security analysis, dependency review                                                                                                                                                                                                                                                                                             |
| `deploy-docs.yml`                                       | Builds this book with mdBook and publishes it to GitHub Pages                                                                                                                                                                                                                                                                    |
| `benchmarks.yml`                                        | Manual: runs `cargo bench`                                                                                                                                                                                                                                                                                                       |
| `nightly.yml`, `release.yml`, `deploy.yml`, `stale.yml` | Scheduled / release automation                                                                                                                                                                                                                                                                                                   |

The CMake minimum, the Rust toolchain and LLVM versions come from `devkit/scripts/setup/config/tool-versions.json`.

## vcpkg: pinned version and binary cache

* **The vcpkg version is the submodule commit.** `third_party/vcpkg` is a git submodule and the commit this repository points to is the vcpkg that every machine and every CI job uses (the Linux/macOS bootstrap, the Windows bootstrap and the macOS CI job follow the same rule; nothing runs `git pull` any more). To move to another version: `git -C third_party/vcpkg fetch origin`, `git -C third_party/vcpkg checkout <commit>`, `git add third_party/vcpkg`, commit. `builtin-baseline` in `vcpkg.json` is separate: it pins the *port* versions (Qt, Vulkan headers, ...). The submodule is not fetched shallow on purpose: vcpkg reads the baseline commit from its own history.
* **Binary cache.** Building Qt from source is what made the C++ jobs slow. `.github/actions/vcpkg-cache` restores a directory of per-package archives before the packages are installed and points vcpkg at it (`VCPKG_BINARY_SOURCES`). The cache key contains the OS and architecture, the compiler, the pinned vcpkg commit, the dependency part of `vcpkg.json` and the target triplets of the presets, so a hit always holds binaries vcpkg would accept.
* **Who writes it.** Only runs on the default branch save the cache (`actions/cache/save` right after the packages are installed). Pull requests only restore it, so they cannot fill the repository's cache quota. `codeql.yml` restores it too.
* **Keeping it alive.** GitHub deletes cache entries that were not used for 7 days, and a runner image update that changes the compiler changes the key. `cache-warm.yml` runs the C++ pipeline every night on the default branch for both reasons. A pull request opened right after an image update, before the next nightly run, builds the packages once itself.
* **Resetting it.** Change the `revision` input of the action (default `1`) to discard every entry.
