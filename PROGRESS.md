## What happened compared to the previous commit? (fix: immutable file mapping)
- decision: memory-mapped archives are held immutable while mapped (the alternative, reading archives into memory, was rejected). Bootstrap download verification is postponed: the packaging/dependency installation moves to a new, faster system outside Bootstrap.
- fixed (fs): `OsFileSystem::mmap_read` opens the file, takes a shared lock (`File::try_lock_shared`) and keeps the file - and with it the lock - inside the new `MappedFile` for as long as the mapping lives (unmapped first, then unlocked). On Windows it also opens with `FILE_SHARE_READ` only, so no process can open the file for writing or delete it while it is mapped. `MmapHandle::Mapped` now holds a `MappedFile` (`is_locked()` reports whether the filesystem supports locks).
- fixed (fs): `OsFileSystem::open_write` takes the exclusive lock *before* truncating (it used to `File::create`, emptying the file first) and fails with `ErrorKind::ResourceBusy` while the file is mapped or being written; the exclusive lock lasts as long as the writer. A file with an open writer cannot be mapped either (no half-written archive). `write_bytes`/`write_archive` replace files by renaming, which leaves a mapped file untouched, so exporting over an archive the game has open is safe: the open one keeps serving its old content.
- fixed (vfs): `PackedArchive::open` maps the archive first and reads the index out of the mapped bytes (new `format::parse_index`; `read_index` still exists and wraps it), so index and data always come from the same file contents; before, the path was opened twice and could be swapped in between.
- limit (documented on `MappedFile`): on Unix the lock is advisory (`flock`). A foreign process that ignores it and truncates the file in place can still break a live mapping; Windows is enforced for every process. A filesystem without lock support (some network/FUSE mounts) maps unprotected.
- tests: `fs/tests/mapped_file.rs` (3) and `an_opened_archive_survives_being_replaced_on_disk` in `vfs/tests/archive_and_fs.rs`. Verified (Rust 1.91.1, Linux): `cargo test -p fs -p vfs -p ffi --all-features` green. Not verified: Windows (share mode / `LockFileEx` behaviour), macOS, clippy and `cargo fmt --check` with the real toolchain.

## What happened compared to the previous commit? (fix: low-severity audit findings)

Noise: the lattice index no longer saturates at `2^31` (the noise froze to one value for every larger coordinate); it wraps, so cells repeat every `2^32` units and stay saturated only beyond `2^63`. Every Perlin/simplex function now returns NaN for a non-finite coordinate (Perlin gave NaN, simplex a silent 0).
- fixed (ccore): `WeakHandle::upgrade` always succeeded; it now takes the storage's liveness check (`upgrade(|id| ...) -> Option<Handle>`; nothing used the old signature). New `GenerationId::checked_next_generation()` (None instead of wrapping). Documented why `Handle::new` stays public (the storage validates generations, a forged handle is just invalid).
- fixed (ffi): `ffi_logger_shutdown`, `add_console_sink`, `add_file_sink`, `set_min_severity`, the diagnostic builder setters and `ffi_diagnostic_builder_emit` return `false` for a null pointer instead of dereferencing it (a null logger leaves the builder to the caller).
- fixed (vfs-macros): `file!`/`file_bytes!`/`metadata!`/`path!` reject `..`, absolute paths, `:` and NUL (they read files at compile time, so `assets://../../x` embedded any file); the root error says `temp://` (it said `temp//`); `metadata!` registers the file as a build dependency (it used to keep stale size/mtime) and honours `SOURCE_DATE_EPOCH` for reproducible builds. Not changed: Enter/Tab are not part of `text()` (by design; they are key events).
- fixed (renderer): new `RenderErrorCode::SurfaceLost` for `VK_ERROR_SURFACE_LOST_KHR` (it was `Unknown`, i.e. fatal); fence waits time out after 10 s and report `DeviceLost` instead of waiting forever on a hung GPU; host-visible buffers are persistently mapped (`Buffer::Write` is a memcpy, not map/unmap per call) and a failed `vmaMapMemory` reports its real VkResult/code instead of "needs a host-visible buffer".
- fixed (runtime): `RendererBridge::DrawFrame` recovers from `DeviceLost` (rebuilds the device) and `SurfaceLost` (rebuilds swapchain and surface) from the remembered window handle, at most 3 times in a row; before, every error ended the process with exit code 2. - tests: new unit tests in `ccore`, `math` (curves, noise), `vfs-macros`, `platform` (paths, input) and `ffi` (null pointers). ## What happened compared to the previous commit? (fix: medium-severity audit findings)
- fixed (vfs): `PackedBackend` now has real directory semantics: `list_dir` returns the *direct* children (files and virtual sub-directories) sorted, matching whole path components (`textures` no longer matches `textures2/...`), a missing directory is `NotFound` instead of `Ok([])`, and `exists`/`metadata` know virtual directories. `HybridBackend::list_dir` merges both layers (sorted, deduplicated) and propagates real errors; only "not found" in one layer is ignored. `LooseBackend::list_dir` is sorted too. `FileManager::list_dir` skips entries that are not valid VFS paths (e.g. a Linux file called `a:b`) instead of failing the whole listing. `VfsError::is_not_found()` is new.
- fixed (vfs): in Release mode every packed root shared one archive but opened (index read + mmap) it again per root; `PackedArchive` is opened once and shared through an `Arc`. Roots are initialised in a fixed order so errors are reproducible.
- fixed (vfs/fs): `write_archive` rejects more than `u32::MAX` entries or paths over `u16::MAX` bytes (they used to be truncated into a silently corrupt archive) and writes `<out>.tmp` then renames, so an interrupted export never leaves a truncated archive. `OsFileSystem::write_bytes` is crash-safe (temp file + `sync_all` + rename; writing through a symlink stays in place). New `FileSystem::rename` (atomic on the OS filesystem). `OsFileSystem::read_dir` skips non-UTF-8 names instead of listing lossy names that do not exist.
- not changed (vfs): `HybridBackend` has no whiteouts - removing an overlay file reveals the archive's original again. That is a design choice; it is now documented on the type.
- fixed (ffi): every `extern "C"` function in `vfs`, `logger`, `diagnostic`, `platform` and `lib` runs inside a panic guard (`guard`, `guard_vfs`, `guard_platform`): a panic becomes the function's failure value (`false`/null) and, for vfs/platform, a last-error entry, instead of aborting the host process. `ffi_*_last_error_message` no longer returns null when the message contains a NUL (it is replaced).
- fixed (log): `FileSink` keeps the previous session's logs as `<name>.previous.log` instead of truncating them (a clean shutdown still deletes the current ones, so a leftover log means the last session died). Log text is escaped (`format::escape_control`): a message can no longer forge log lines or inject terminal escape sequences. `NativeLogVfs` only accepts plain relative names (no `..`/absolute). `Logger` calls sinks without holding its lock (a sink may add a sink while emitting), and no `Logger`/`FileSink`/producer lock panics on poisoning.
- fixed (log-core): runtime producer registration validates the code (1-128 ASCII letters/digits/`-`/`_`), caps name lengths and the number of registrations (1024; each one leaks its strings). A duplicate *static* producer code only panics in debug builds now; release keeps the first registration instead of aborting at the first log call. Not changed: a runtime code may still start with `CV-` (the engine's own C++ renderer registers `CV-RENDERER` that way), so routing by prefix can still be spoofed by whoever registers first.
- fixed (platform): `open_url` requires `//` and a host for http(s) (no `http:C:\...`, no backslashes) and refuses `mailto:` links with an `attach`/`attachment` parameter.
- fixed (CI): every GitHub Action in `.github/workflows` is pinned to a commit SHA (tag in a trailing comment; Dependabot keeps updating them). `dtolnay/rust-toolchain` is pinned with an explicit `toolchain: stable` input, because by SHA it can no longer read the toolchain from the ref.
- not fixed (CI): the bootstrap scripts still download installers (GitHub release assets, `vs_buildtools.exe`, Homebrew's install script, rustup) without checksum/signature verification; that needs per-version hashes maintained in `tool-versions.json`.
- tests: `vfs/tests/{release_mode,archive_and_fs}.rs`, `log-core/tests/{format_safety,producer_limits}.rs`, `log-sinks/tests/file_sink.rs`, plus unit tests for the FFI guard and the URL checks. Verified in the sandbox (Rust 1.91.1): `cargo test -p fs -p vfs -p log-core -p log-sinks -p ffi --all-features` and `cargo test -p platform --lib process` all green. Not verified: clippy / `cargo fmt --check` with the real toolchain (formatted with an older rustfmt, imports kept in the 2024 style), the C++ tests and workflows, Windows/macOS.

## What happened compared to the previous commit? (Phase 6.4, superseded by the entry above but kept for history)
- added (Phase 6.4): `renderer::FrameSync` (renderer/FrameSync.hpp) - the frame-level synchronization abstraction. `RenderDevice::CreateFrameSync()` builds it; `BeginFrame(swapchain)` waits for the in-flight slot's previous frame, acquires an image (100 ms timeout, so a hidden window can never block the GUI thread) and hands out a reset command buffer; `EndFrame(swapchain, frame)` submits and presents. Semaphores/fences stay inside the backend (acquire semaphore + fence + command buffer per in-flight slot, render-finished semaphore per swapchain image); a rebuilt swapchain is noticed by the next `BeginFrame()`, no extra call. Vulkan implementation in VulkanRenderDevice.cpp; `framesInFlight` is clamped to [1, 8].
- added (Phase 6.4): the editor render loop. `ViewportRenderer` owns a `FrameSync` (after the swapchain, so it dies first) and renders from a ~60 Hz timer on the GUI thread: a clear to a slowly cycling color, FPS in the status bar. The loop rests while the viewport is hidden or the window is minimized, and while the swapchain cannot be rebuilt yet (zero-sized viewport, failed rebuild - retried on the next resize and every 250 ms). `rebuildSwapchain(force)` no longer skips a rebuild just because the size is unchanged, so `OutOfDate` is always handled. Fatal errors (device lost, failed submit/present) stop rendering and show up in the status bar; recovering from them is not implemented.
- added: `Swapchain::Acquire(semaphore, timeoutNs)` and `SwapchainStatus::NotReady` (timeout expired, nothing acquired). `VK_ERROR_DEVICE_LOST` / `VK_ERROR_OUT_OF_*_MEMORY` now map to `RenderErrorCode::DeviceLost` / `OutOfMemory` for acquire, present, submit and begin/end instead of `Unknown`.
- added: validation as a test signal. `renderer::ValidationErrorCount()` (renderer/Diagnostics.hpp) counts validation-layer errors, `RenderDevice::IsValidationEnabled()` says whether the layer is running, `RENDERER_FORCE_VALIDATION` (CMake option) enables the layer in every build type. Linux CI installs `vulkan-validationlayers`, configures with the option and sets `CV_REQUIRE_VALIDATION=1`, which makes the tests fail if the layer is not actually running.
- added: `frame_sync_test` (gpu): 1, 2 and more-frames-than-images in flight, ~140 frames each with a resize in the middle, Acquire timeout, misuse checks, move semantics, zero validation errors. `editor --smoke-frames N` + ctest `editor_render_smoke` (labels `gpu;editor`): the real Qt window renders N frames, is resized half-way, quits by itself and must find no validation errors. CI runs it in its own step; it was non-blocking while the vcpkg Qt xcb plugin was unverified and is a regular gate now (see the P0 entry above).
- note: `AcquireCommandBuffer()` allocates a new command buffer on every call and only frees them at `Shutdown()` - use it once per long-lived buffer; per-frame buffers come from `FrameSync`. Documented on the function.
- note: `Submit()` still waits at the TRANSFER stage (right for a clear). The first real graphics pass must change it to COLOR_ATTACHMENT_OUTPUT (comment in `VulkanRenderDevice::Submit`).
- note: nothing is drawn in the viewport except the clear color yet.
